# Doc-agent memory ledger (robotsix-cost-monitor)

## Doc layout
- `README.md` — features, setup, CLI table, full HTTP API table (method/path/query/response), architecture + contributing/standards links.
- `docs/index.md` — MkDocs index linking to api.md, configuration.md, cli.md, README.
- `docs/api.md` — mkdocstrings `automodule` blocks, one per flat module.
- `docs/reference/configuration.md` — config reference: `Config`/`Settings`/`AuthConfig` tables + env vars.
- `docs/reference/cli.md` — CLI reference.
- `ARCHITECTURE.md` — directory layout, data-flow diagram, "How a request flows", background-loop lifecycle table, key invariants.
- `docs/modules.yaml` — module taxonomy for CI; every new source/test file must be registered here, else module-validation fails.
- `CHANGELOG.md` — Keep a Changelog, single `0.0.0 (unreleased)` section, new entries prepended at top.

## Conventions
- User-facing changes → CHANGELOG entry (prepend under `0.0.0 (unreleased)`).
- Config field changes → `docs/reference/configuration.md` tables + `config/config.example.json`.
- Cache/requests/background-loop behavior → `ARCHITECTURE.md` (data flow, loop table, key invariants).
- API endpoint/query changes → README API table (+ `_CHAT_SKILL` in `routes.py` if the chat agent should know).
- Auto-generated refs (api.md) need no edits — mkdocstrings pulls from source docstrings.

## CostService cache (current)
- Single unified in-memory TTL cache (SWR) keyed by `(project_slug, window_hours)`, holding a `WindowData` snapshot with all five data kinds: traces, model_usage, backend_cost, agent_usage, trace_count. Fetched as a unit via `asyncio.gather`.
- `DASHBOARD_WINDOW_PRESETS = (1, 6, 24, 168)` — pre-warmed by `_warm_cache` at startup and by `_cache_refresh_loop` (cadence `dashboard_refresh_interval_seconds`, default 120s).
- Stale-while-revalidate: fresh served immediately, stale served + bg refresh, cold miss blocks. `POST /api/refresh` invalidates all keys. `last_updated` is a single per-refresh timestamp.
