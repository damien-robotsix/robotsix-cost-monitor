New stuck-ticket detection feature:
- `clients/mill.py` — `MillClient` class queries `GET /tickets` on the robotsix-mill board API, identifies tickets in non-terminal states (draft, human_issue_approval, ready, documenting, code_review, etc.) whose `updated_at` is older than `stuck_ticket_threshold_hours`. Raises `MillAPIError` on failure (distinct from empty result). API key resolved via `resolve_mill_api_key()` in config.py (DEPLOY_API_KEY env var or settings.mill_api_key).
- `app.py` — `_stuck_ticket_loop(mill, interval_s)` background task spawned in lifespan when `stuck_ticket_check_interval_seconds > 0` and `mill_base_url` is set. On `MillAPIError`, keeps previous gauge value. Logs warning with stuck ticket details. Increments `stuck_ticket_check_runs` counter, sets `stuck_ticket_count` gauge.
- `routes.py` — `GET /api/stuck-tickets` returns fresh results, 503 on `MillAPIError`.
- `metrics.py` — Two new metrics: `stuck_ticket_check_runs_total` (Counter) and `stuck_ticket_count` (Gauge).
- Config fields: `mill_base_url`, `mill_api_key` (SecretStr), `stuck_ticket_threshold_hours` (default 48, 0=disable), `stuck_ticket_check_interval_seconds` (default 600).
